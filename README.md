# وصّلني – الخادم وقاعدة البيانات

## 1) تشغيل محلي
1. نزّل Node.js (18+) و PostgreSQL.
2. `createdb waslni`
3. انسخ `.env.example` إلى `.env` وعدّل القيم.
4. `npm install`
5. `npm run db:init`   (ينشئ الجداول)
6. `npm start`  ← الخادم على http://localhost:3000

## 2) إنشاء حساب أدمن
سجّل حساب عادي من التطبيق ثم نفّذ:
`UPDATE users SET role='admin' WHERE phone='رقمك';`

## 3) الاستضافة (اختار واحد)
- Railway / Render: ارفع المجلد، أضف Postgres، وحط `DATABASE_URL` و `JWT_SECRET`، ونفّذ schema.sql مرة واحدة.
- Supabase: ممكن تستخدمه كقاعدة Postgres مُدارة وتنفّذ schema.sql في SQL Editor.

## 4) تجربة الواجهة فورًا
بعد `npm start` افتح http://localhost:3000 — الخادم بيقدّم الواجهة من مجلد www.

## 5) تحويل الواجهة لتطبيق موبايل (Capacitor)
قبل البناء: في www/index.html غيّر `API_URL` لعنوان خادمك (لازم https). ملف capacitor.config.json جاهز.
```
mkdir waslni-app && cd waslni-app
npm init -y
npm i @capacitor/core @capacitor/cli @capacitor/android @capacitor/ios @capacitor/geolocation @capacitor/push-notifications
npx cap init "وصّلني" com.waslni.app --web-dir=www
mkdir www   # حط فيه index.html (الواجهة)
npx cap add android
npx cap sync
npx cap open android   # يفتح Android Studio لبناء APK/AAB
```
بعد كده الواجهة تتكلم مع الـ API بدل localStorage، ومعاها GPS حقيقي عن طريق Geolocation.

## 6) الإشعارات (Firebase)
1. أنشئ مشروع في https://console.firebase.google.com وأضف تطبيق Android بالاسم `com.waslni.app`.
2. نزّل `google-services.json` وحطه في `android/app/` (بعد `npx cap add android`).
3. Project settings ← Service accounts ← Generate new private key. حط محتوى الـ JSON في سطر واحد في متغير `FIREBASE_SERVICE_ACCOUNT` على الخادم.
4. لـ iOS: ارفع مفتاح APNs في Firebase وفعّل Push Notifications في Xcode.
بدون الخطوات دي التطبيق يشتغل عادي، والإشعارات بتظهر جوه التطبيق بس.

## 7) الخرائط والهوية
- الخرائط: Leaflet + بيانات OpenStreetMap وخلفية داكنة من CARTO. مناسبة للتجربة والاستخدام الخفيف؛ لحجم كبير استخدم مزوّد مدفوع (Mapbox / Google Maps).
- تحويل العنوان من الإحداثيات بيستخدم Nominatim المجاني (حدود استخدام)؛ للإنتاج استبدله بخدمة تجارية.
- الأيقونة في `www/icon.svg`. لتوليد أيقونات الموبايل: حوّلها PNG بحجم 1024 وضعها في `assets/icon-only.png` ثم `npx @capacitor/assets generate`.
- ألوان الهوية: أسود `#07080C` • أزرق `#2E6BFF` • سماوي `#35D0FF` للأرباح والتأكيدات.

## 8) توثيق الهوية (جديد)
- المندوب لازم يوثّق حسابه قبل تقديم أي عرض: الرقم القومي (بيتحقق منه التطبيق والخادم: 14 رقم، تاريخ ميلاد صحيح، كود محافظة، سن 18–75) + صورة وش وضهر البطاقة + سيلفي مباشر بالكاميرا + نوع المركبة. العميل توثيقه اختياري.
- الأدمن بيراجع الطلبات من تاب "التوثيق" (بيشوف الرقم القومي والصور) ويوافق أو يرفض بسبب يوصل للمستخدم كإشعار.
- لو شغّلت schema.sql قبل كده: نفّذ `migration_001_verification.sql` فقط. لو لسه: schema.sql فيه كل حاجة.
- الرقم القومي بيتخزن مشفّر (AES-256-GCM) بالمفتاح `ENC_KEY` — احتفظ بنسخة منه ولا تغيّره بعد الإطلاق. ولمنع تكرار نفس الهوية بيتخزن بصمة (HMAC) فريدة.
- الصور بتتحفظ في مجلد `uploads/` وهو **غير متاح للعامة**؛ بتتقدّم عبر API بتوكن فقط (الأدمن، صاحب الصورة، أو العميل اللي المندوب قدّم له عرض). للإنتاج الأفضل تخزينها في تخزين سحابي خاص (S3 أو ما يماثله) مع نسخ احتياطي.
- مهم: بيانات الهوية بيانات شخصية حساسة؛ راجع متطلبات قانون حماية البيانات الشخصية المصري (151 لسنة 2020) وسياسة خصوصية وفترة احتفاظ مع مختص قانوني قبل الإطلاق.
- لم يُضف تحقق تلقائي (مطابقة الوجه أو قراءة البطاقة OCR) ولا كود OTP على الموبايل: الأول يحتاج خدمة KYC مدفوعة، والثاني مزوّد SMS (مثل Twilio أو مزوّد محلي).

## 9) حساب الإدارة وكود الإدارة (جديد)
- عيّن متغير `ADMIN_CODE` (نص سري طويل). من شاشة التسجيل اضغط «تسجيل كإدارة (بكود سري)» واكتب الكود لإنشاء حساب إدارة. الكود بيتفحص في الخادم فقط، وفيه حد 5 محاولات كل 15 دقيقة.
- لو ما حددتش `ADMIN_CODE` التسجيل كإدارة بيتقفل تمامًا (والبديل `node make-admin.js رقمك`).
- بعد إنشاء حسابات الإدارة اللازمة، الأفضل تغيّر `ADMIN_CODE` أو تمسحه من الإعدادات.

## 10) لوحة الإدارة والـ APIs الجديدة
- لوحة تحكم بفترات (7/30/90 يوم/الكل): مؤشرات مالية، أداء، مستخدمين، رسوم بيانية يومية، توزيع الحالات، أفضل المناديب، آخر الطلبات، وتنبيهات.
- إدارة الطلبات (بحث/فلترة/إلغاء) والمستخدمين (بحث/إيقاف/رفع إيقاف) والبلاغات وسجل العمليات وتصدير CSV.
- للمستخدمين: إشعارات مخزّنة، عناوين محفوظة، إلغاء الطلب، بلاغات، أرباح المندوب، تعديل الاسم وكلمة المرور.
- القائمة الكاملة في `API.md`. لو شغّلت النسخة القديمة: التشغيل التالي بيضيف الجداول الجديدة تلقائيًا (`migration_002_admin_features.sql`).

## 11) الملف الشخصي (المرحلة 1)
- صورة شخصية ونبذة (حتى 300 حرف) لكل المستخدمين: تاب «حسابي» ← 🖼️ الصورة / 📝 النبذة. الضغط على صورة مندوب في العروض أو الطلبات بيفتح ملفه الشخصي.
- الخصوصية: الملف بيظهر لصاحبه والإدارة ولمن بينهم تعامل فعلي (طلب/عرض مشترك). رقم الهاتف مش بيظهر في ملف حد تاني.
- قاعدة البيانات: عمودان جديدان في `users` (`bio`, `avatar`) — بيتضافوا تلقائيًا عند التشغيل (`migration_003_profile.sql`) بدون مساس بالبيانات الحالية.
- اختبار المنطق بدون قاعدة بيانات: `npm run test:profile`

## 12) التحقق من الهاتف OTP (المرحلة 2)
- التسجيل (غير الإدارة): إدخال البيانات ← كود SMS ← إنشاء الحساب. الدخول لم يتغير.
- **لازم تفعّل مزوّد الرسائل** وإلا لن يمكن إنشاء حسابات جديدة: `SMS_PROVIDER=twilio` و`TWILIO_ACCOUNT_SID` و`TWILIO_AUTH_TOKEN` و`TWILIO_FROM` (أو `TWILIO_MESSAGING_SERVICE_SID`). التفاصيل في `.env.example`.
- لمزوّد آخر (محلي مثلًا) تُضاف دالة إرسال في `sms.js` فقط.
- ترقية قاعدة قديمة تلقائية (`migration_004_otp.sql`): جدول `phone_otps` وعمود `users.phone_verified_at`.
- اختبار المنطق بدون قاعدة بيانات: `npm run test:otp`

## 13) تعدد الأدوار + لوحة الإدارة المنفصلة (المرحلة 3)
- **حساب واحد = عميل و/أو مندوب.** جدول `user_roles` (migration_005_roles.sql، بيتنفّذ تلقائيًا مع `npm start` ويملأ الأدوار من الحسابات القديمة). `users.role` ما اتغيّرش، وعمود `users.last_role` بيحفظ آخر دور اتستخدم.
- التوكن فيه `role` = **الدور النشط** (فكل `auth('courier')` القديمة شغالة زي ما هي) + `roles`. الجلسات القديمة (بدون `roles`) بتشتغل عادي.
- المسارات: `GET /me/roles` • `POST /me/roles {role}` (إضافة صفة customer/courier) • `POST /me/switch-role {role}` (توكن جديد) • `POST /verification/vehicle` (نوع المركبة لحساب موثّق كعميل ثم أضاف صفة مندوب).
- الإدارة حساب منفصل: لا يُضاف له ولا منه أدوار.
- قواعد الأمان: المندوب لا يقدّم عرضًا على طلبه هو، وطلباته لا تظهر له في «فرص»، ولا يتبلّغ بها. المندوب لازم يكون موثّق ومعاه نوع مركبة قبل أي عرض.
- **لوحة الإدارة المنفصلة:** افتح `/admin.html` (حسابات الإدارة فقط، جلسة منفصلة عن التطبيق): اللوحة، الطلبات، الأعضاء (بكل صفاتهم)، التوثيق (منتظر/موافق/مرفوض)، البلاغات، العمولة والسجل والتصدير. بتستخدم نفس واجهات `/admin/*` الموجودة. إدارة `index.html` لسه موجودة كما هي.
- الاختبارات: `npm run test:roles` • `npm run test:front` • `npm run test:admin` (بجانب `test:profile` و`test:otp` و`npm run check`).

## 14) الاتصال التلقائي بالخادم (بدون رسائل وبدون روابط)
- الواجهة (`index.html`) ولوحة الإدارة (`admin.html`) بيدوّروا على الخادم لوحدهم بصمت بالترتيب: `API_URL` (لو اتحدّد) ← آخر عنوان نجح ← نفس الدومين اللي فتح الصفحة ← الجهاز نفسه (`localhost` على بورتات 3000/8080/5000). مفيش أي رسالة عن الخادم بتظهر للمستخدم؛ لو الاتصال انقطع بيعيد المحاولة وحده، وبيظهر بس شريط التحميل الرفيع.
- طلبات القراءة بتتعاد تلقائيًا عند الانقطاع أو لما الخادم يصحى (502/503). **عمليات الكتابة (طلب/دفع/…) ما بتتعادش لوحدها** عشان ما تتكررش؛ بتستنى الاتصال قبل ما تتبعت.
- **عشان يفتح من أي جهاز بدون رابط:** استضف الخادم (راجع DEPLOY.md / render.yaml) وحط عنوانه مرة واحدة في `API_URL` أعلى السكربت في `www/index.html` و`www/admin.html` (مثال: `const API_URL="https://waslni.onrender.com";`). بعدها الملف أو تطبيق الموبايل بيشتغل مباشرة.
- لو الخادم شغال على نفس جهازك (`npm start`) وفتحت `index.html` مباشرة بيتلقّط تلقائيًا على `localhost`.
- الاختبار: `npm run test:connect`.

- عنوان الخادم المستضاف الحالي (Railway) متسجّل في `API_URL` في `www/index.html` و`www/admin.html`: `https://waslni-production-e28fe835.up.railway.app`.
